2026-10-08 한 세션 안에서 세 차례 파일이 예고 없이 사라진 걸 관찰함: `CLAUDE.md`, `.claude-plugin/` 전체, `docs/supabase-schema.sql`. 세 경우 모두 Claude가 삭제한 적이 없고, 직전 턴까지는 분명히 존재를 확인했다가 다음 명령에서 사라져 있었음.

`docs/supabase-schema.sql` 건은 사용자에게 직접 확인한 결과 **사용자의 실수 삭제**였음("실수로 지웠어요, 매 해주세요"). `CLAUDE.md`/`.claude-plugin/` 건은 원인을 묻지 않고 넘어갔음(당시엔 작업과 무관하다고 판단).

**추가 사례(같은 세션, 더 뒤):** `admin/.env.example`, `frontend/.env.example` 두 파일도 예고 없이 사라진 채 발견됨. 이번엔 확인 결과 **사용자가 의도적으로 지운 것**이었음("일부러 지웠어요, 그대로 커밋"). 즉 이 패턴은 사고일 때도, 의도된 정리일 때도 둘 다 있다 — 어느 쪽인지 절대 추측하지 말고 매번 물어야 한다.

**Why:** 패턴이 반복되는 걸 보면 사용자가 터미널/파인더에서 수동으로 파일을 정리하거나, 동시에 다른 도구(에디터 자동 정리, 다른 Claude Code 세션 등)가 같은 디렉터리를 건드리고 있을 가능성이 있음. 원인을 단정하지 않되, "방금 전에 읽은 파일이 지금도 있다"고 가정하지 않는 게 안전함. 실수/의도 비율이 반반이라 "또 실수겠지" 혹은 "또 의도적이겠지" 식의 지레짐작도 둘 다 위험함.

**How to apply:** 이 저장소에서 파일을 옮기거나(`git mv`) 참조하기 전에, 특히 이전 턴에서 읽은 지 시간이 좀 지난 파일이라면 존재 여부를 먼저 확인할 것(`ls`/`git ls-files`). 파일이 사라진 걸 발견하면 조용히 재생성하지도, 조용히 커밋하지도 말고 — 원인을 사용자에게 먼저 물어본 뒤(실수 삭제인지, 의도된 변경인지) 복원할지 그대로 커밋할지 결정한다. 복원이 필요하면 같은 대화 안에서 이전에 읽었던 원본 내용을 그대로 재사용할 수 있다.
