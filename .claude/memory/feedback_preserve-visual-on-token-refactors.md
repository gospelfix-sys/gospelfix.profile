디자인 토큰 체계를 새로 도입하거나 정리할 때(예: shadcn/ui 스타일 `--radius`/그림자 규칙 도입), 사용자는 "새 시스템의 권장 기본값으로 교체" 옵션보다 "현재 화면에 보이는 시각적 크기/느낌을 그대로 유지" 옵션을 선택한다.

**Why:** 2026-09-20, GospelFix 프로필 사이트에 shadcn 기반 디자인 아이덴티티를 도입하면서 두 가지 지점에서 선택지를 제시했다 — (1) 버튼/카드 모서리 반경을 지금 크기로 유지할지 shadcn 기본값(더 각짐)으로 바꿀지, (2) 그림자를 지금처럼 버튼/컨테이너에도 쓸지 shadcn 권장대로 카드류에서 완전히 제거할지. 두 질문 모두 "현재 유지"를 선택했다. 이 사이트는 이미 완성되어 배포 중인 개인 프로필이라, 시스템의 이론적 순수성보다 기존에 확인된 시각적 결과를 깨지 않는 것이 더 중요하다는 판단으로 보인다.

**How to apply:** 이 저장소에서 디자인 시스템/토큰 리팩터링을 제안할 때는, 시각적으로 눈에 띄는 변화가 생기는 지점(모서리 크기, 그림자 유무, 색상 톤 등)마다 "현재 유지" 옵션을 기본 추천으로 먼저 제시하고, 명시적으로 바꿔달라는 요청이 없으면 코드 리팩터링은 계산된 픽셀 결과가 기존과 동일하도록(zero visual diff) 설계한다. 실제로 `--radius-full: 50%`→`9999px` 리팩터링 중 정사각형이 아닌 요소(핸들바)에서 의도치 않게 타원으로 바뀌는 회귀가 한 번 발생했었다(`docs/08-guidelines.md`의 "겪은 문제" 표에 기록됨) — 이런 계산 결과 불일치는 버그로 취급해 바로 잡는다.
