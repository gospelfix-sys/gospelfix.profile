사용자가 카드 콘텐츠(제목/설명/태그)를 링크 하나만 주고 "알아서 채워달라"고 요청하면, URL 슬러그에서 의미를 유추해 채우지 말고 WebFetch로 실제 페이지 내용을 확인한 뒤 채운다.

**Why:** 2026-09-15, 사용자가 `https://mongolia-employment.vercel.app/` 링크만 주고 "너가 알아서 일단 예시로 넣어줘"라고 해서, URL의 "employment"만 보고 "몽골 취업 지원 사역"이라는 제목/설명을 지어냈다. 실제로는 2026년 6월 28일~7월 4일 몽골 단기선교팀을 위한 사이트(기도편지, 준비 자료, 일정표 등)였고 취업 지원과는 전혀 무관했다. 사용자가 "사이트를 확인하고 다시 정의해달라"고 요청한 뒤에야 WebFetch로 실제 내용을 파악해 제목("몽골 단기선교"), 날짜(2026.06.28-07.04), 설명, 태그를 전부 고쳤다. URL 이름만으로 내용을 추측하는 건 신뢰할 수 없다는 게 확인된 사례.

**How to apply:** 이 저장소(또는 유사하게 카드/콘텐츠에 외부 링크를 다는 작업)에서 링크만 주어지고 내용을 채워야 하면, "임시로 채워달라"는 요청이라도 먼저 WebFetch로 링크를 확인한 뒤 그 내용을 근거로 채운다. URL 문자열에서 유추한 내용은 임시로도 신뢰하지 말 것.

**추가 사례 (2026-09-30):** `https://gbc-sys.github.io/holy.win.2026/`(홀리윈 2026 전도 대상자 기도 페이지)를 WebFetch로 확인했을 때, 제목/설명/태그는 페이지에서 그대로 얻을 수 있었지만 **행사 날짜(date 필드)는 페이지 어디에도 없었다**. WebFetch로 확인했다고 해서 카드에 필요한 모든 필드가 다 나온다는 보장은 없다 — 확인 후에도 빠진 필드(특히 날짜처럼 그럴듯하게 지어내기 쉬운 값)는 추측하지 말고 [[feedback-card-order-is-array-order]]처럼 사용자에게 직접 물어서 채운다.
